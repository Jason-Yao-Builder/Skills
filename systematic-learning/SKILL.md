# Systematic Learning Skill

一个完整的"学→考→评→存"闭环。不考记忆和背诵，只考对原理的理解、架构能力和实践判断。

---

## 触发条件

用户消息中出现以下关键词时触发：
- "系统性学习"
- "课题学习"

---

## 核心流程（必须执行）

```
可选：资料搜集
      ↓
对话式讲解（费曼法）
      ↓
出测试题（8-12 题）
      ↓
逐题评分与评析
      ↓
生成文件归档
      ↓
可选：Project 建议
```

---

## 第零步：启动（每次进入时必做）

`<学习目录>` 使用用户已有的学习归档位置；未配置时，在当前工作目录下使用 `learning/`。已有明确课题或资料搜集偏好时，直接沿用，不重复询问。

1. **读取学习索引**：读 `<学习目录>/索引.md`
   - 如果文件存在，了解用户过往学习进度、薄弱点
   - 如果不存在，跳过
2. **问用户两件事**：
   - 今天的学习课题是什么？
   - 要不要帮忙搜集资料/预研？（如用户自带资料则跳过）

## 第一步：对话式讲解

### 方法：费曼式 + 建造者视角

- 以"设计者当时面对什么问题"为起点
- 从最朴素的想法出发 → 暴露问题 → 自然引出下一层解法
- 专业名词在推导出它的那一刻才出现
- 抽象机制必配具体场景逐帧走一遍
- 鼓励用户提出"对抗性假设"（"我认为 X 是这样的，你来反驳"）

### 关键纪律

- 用户问"不懂"时不要重复同一个解释，换一个切入角度
- 用户给出错误理解时直接纠正，不恭维
- 用户理解到位时简短确认，不拖沓

---

## 第二步：出测试题

### 出题原则

- 总题数：8-12 题
- **绝不考记忆/背诵**——只考理解、推理、判断
- 题型参考（不限于此）：情景判断、反事实推理、边界判断、概念辨析、类比迁移、逆向思考、架构理解、生态博弈。**不要拘泥于这些列举的题型**——根据课题特点自由创造新的考察形式，能考出真实理解就是好题
- 难度上大致有梯度感即可（不用机械三等分），整体从基础概念过渡到综合分析

### 出题风格偏好（必须遵守）

**核心模式：情境 + 矛盾/约束 → "你怎么办"**

好题的结构是：给一个具体场景，场景中包含张力或约束条件，然后问用户如何判断/选择/处理。考察点藏在情境里，不直接点明。允许多种合理答案，评分看推理质量。

**必须避免的出题模式：**
- ❌ "反驳 X" / "证明 Y 是对的"——预设立场，压缩答题空间
- ❌ 答案唯一且只需背诵阈值/参数就能答对的题——变成记忆考察
- ❌ "A 和 B 有什么区别"——太直白，容易变成复述定义

**好题示例：**
- 给一个约束条件（比如模型不支持某能力），问用户怎么设计替代方案，每种方案代价是什么
- 给一个具体的数据/状态快照，问用户如何做决策、优先处理什么
- 给两种方案 + 两种使用场景，问用户分别推荐哪个、为什么
- 给一个用户请求 + 系统原则冲突，问用户怎么处理

### 巩固机制

如果索引中记录了前次学习的薄弱点：
- 在新试卷中加入 1-2 题涉及旧知识点
- **优先**：将旧薄弱点与新知识点组合考察（跨知识点融合题）
- **次选**：如果实在无法组合，单独出 1 题考察旧知识点

### 产物

将试题写入文件：`[课题文件夹]/试题.md`

## 第三步：逐题评分与评析

### 评分流程

用户逐题（或批量）回答后：
- 逐题打分（1-10）
- 指出答对了什么、答错了什么
- 给出标准答案和关键推理链
- 答错的题要解释**为什么用户会这么想**以及**正确的思考路径**

### 评分标准

**基础分（满分 10）：**

| 维度 | 权重 | 说明 |
|------|------|------|
| 核心逻辑/判断是否正确 | 70% | 关键结论对不对、因果关系对不对 |
| 推理链是否完整 | 20% | 有没有漏掉关键环节 |
| 表述精度 | 10% | 措辞是否严谨（非核心，不重罚） |

**额外扣分（上限 -10%）：**
- 表述冗长、把逻辑讲得过于复杂

**额外加分（上限 +20%）：**
- 超出预期的、对核心逻辑的自然延展和实践性思考
- 前提是确实精彩且有道理，不是单纯多说了几句

**评分纪律：**
- 核心逻辑全对 + 表述有小瑕疵 → 不应低于 8 分
- 核心逻辑有实质性错误 → 不应高于 6 分，无论表述多流畅
- 同样得 7 分的两个回答，如果一个是"逻辑对但不完整"、另一个是"逻辑错但表述好"，评分时要把差异体现出来，不能给一样的分

## 第四步：生成文件归档

### 必须生成的文件（3 个 + 1 个可选更新）

**文件 1：回答与评析**
- 路径：`[课题文件夹]/[日期]_[主题关键词]_回答与评析.md`
- 内容结构：
  ```
  # [主题] — 回答与评析
  日期：yyyy-mm-dd
  主题：xxx

  ## 第 N 题：[题目主题]
  ### 我的回答
  （整理用户原话，保留核心逻辑）
  ### 评析与标准答案
  得分：X/10
  ✅ / ❌ 判断 + 标准答案 + 关键推理链

  ...（逐题）

  ## 复盘总结
  ### 总分：XX / 100
  ### 强项（抽象一层）
  ### 待提升（抽象一层 + 心法建议）
  ```

**文件 2：学习报告**（写给未来 AI/教练看的）
- 路径：`[课题文件夹]/学习报告.md`
- 内容：极简，≤300 字
- 结构：
  ```
  # 学习报告
  日期：yyyy-mm-dd
  课题：xxx
  总分：XX/100

  ## 讲了什么
  （2-3 句话概括）

  ## 测了什么
  （列出考察的核心能力维度）

  ## 强项
  （1-2 点，抽象描述）

  ## 需要巩固
  （1-3 个具体知识点/思维模式，要具体到可以出题考的程度）
  ```

**文件 3：更新学习索引**
- 路径：`<学习目录>/索引.md`
- 如果不存在则创建
- 结构：
  ```
  # 学习索引

  | 课题 | 路径 | 最近学习 | 总分 | 需巩固 |
  |------|------|----------|------|--------|
  | 示例课题 | 示例大类/01-模块/ | YYYY-MM-DD | 示例分数 | 待巩固知识点 |
  | ... | ... | ... | ... | ... |
  ```

**文件 4（可选）：更新 Roadmap**
- 路径：`[大类]/Roadmap.md`
- 触发条件：根据用户当天的回答和对事物的理解，判断是否需要更新 Roadmap——比如：
  - 用户展现出对某个后续模块的兴趣或天然理解 → 调整模块优先级
  - 用户的薄弱点暗示需要补一个前置模块 → 新增模块
  - 对话中自然涌现了新的学习方向 → 追加到 Roadmap
- 不强制每次都改，有需要才动

### 文件夹结构规范

```
<学习目录>/
├── 索引.md
└── [大类]/                          ← 如"AI Agent 架构"
    ├── Roadmap.md                   ← 该大类的学习路线
    └── [序号]-[模块名]/              ← 如"01-Function Call与MCP基础"
        ├── 试题.md
        ├── [日期]_[关键词]_回答与评析.md
        └── 学习报告.md
```

## 可选：Project 建议

测试结束后问用户：**"要不要我基于今天的内容建议一个练手 Project？"**

如果用户要，给出建议时遵循：
- 优先兼顾**练手 + 实用**（能解决现实生活/工作中的问题）
- 规模尽量小（最小可验证），不超过半天能做完
- 说清楚这个 project 巩固了今天哪个知识点

## Skill 调用示例

**用户输入**：
> 我想系统性学习 [某个主题]

**Skill 行为序列**：

1. 读取 `索引.md`，了解用户历史学习情况
2. 问用户要不要帮搜集资料
3. 进入费曼式对话讲解（用户提问 → 解答 → 用户再问 → 直到双方都觉得讲清楚了）
4. 出 8-12 道测试题，写入 `试题.md`
5. 用户作答，逐题评分评析
6. 生成三个文件（回答与评析、学习报告、更新索引）
7. 问用户要不要 Project 建议

---

## 适用边界

**擅长**：
- 技术概念与架构（AI Agent、分布式系统、协议设计等）
- 制度/机制原理（金融、政策、组织设计）
- 方法论学习（设计模式、思维模型、研究方法）

**不擅长**：
- 纯技能训练（打字速度、画画、乐器）
- 需要大量实操才能学会的东西（只靠对话不够，必须配 Project）
- 考试应试（这个 skill 反对背诵，如果目标是应试请直接说）

## 与其他 skill 的配合

- 如果学习结束后要做 Project，Project 的管理走正常的 Codex 工作流
