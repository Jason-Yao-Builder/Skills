# 活动阅读方法

## 目标与优先级

从本次群聊材料中完整提取可实际参加的线上、线下活动。始终结合 `config/interests.md` 理解背景，但本方法的收录要求优先：**保留所有符合条件的线下活动，同时保留可参加的线上活动；不得因兴趣、城市、主题不相关、相关性评分低或条数上限而隐藏、删除活动。** 个性化只用于排序和可选注释。

不对全部群聊做泛化摘要。不要单独摘录人物发言、人物动态、热点新闻或“某某做了什么”。

## 怎样认定活动

面向参与者的具体组织活动可以收录，例如聚会、讲座、论坛、沙龙、工作坊、黑客松、比赛、线上直播交流、公开课及明确可报名课程。收费活动也可收录，费用未知则留空。招聘会属于活动；普通招聘职位交给招聘方法。

- 有尚可参加的机会，或已报名者仍可参加：状态 `open`，并说明实际参加方式。不要把“报名截止”直接等同于“已报名者不能参加”。
- 时间、参加方式或报名状态不够明确，但确实存在具体活动线索：状态 `uncertain`，说明待核实事项，不能把它伪装成可立即报名。
- 取消、延期、售罄、报名截止等消息必须结合上下文处理；明确取消为 `cancelled`，确认没有参加机会为 `closed`。失效信息可用于更新此前同一活动，不作为推荐的新活动。
- 以本次给定的判断时间和消息时区解释“今晚”“明天”等相对时间；跨日消息不能统一按报告生成日计算。没有可信日期时不要补造。

以下内容不单独形成活动卡片：已结束活动回顾、发言摘录、录播回放、普通新闻、产品或模型发布消息、一般观点、教程下载、资源分享、普通招聘、没有具体组织参与机会的商品推广。可参加发布会与单纯发布新闻需区分。

## 读消息、海报和链接

把文字、附近说明、引用回复、图片海报与链接卡片合并理解。不要只依赖“活动”“报名”关键词，避免漏掉图片邀请和“今晚一起……”的具体聚会。

时间、地点、费用、主办方、截止、参加方式均只能来自给定材料。链接须是输入中实际出现的原始地址，不根据标题猜网址；没有链接但有明确地点、联系或口令时，用文字保留参加方式。图片有二维码但未解出地址时，说明二维码参加方式，不虚构链接。

个人新闻中的嘉宾姓名只在描述可参加活动议程时有用。不要把“这个嘉宾值得关注”扩写成独立人物动态。

## 合并与输出

同一活动跨群出现时合并，保留所有直接支持结果的来源。标题相似但日期、场次或地点不同则不合并；活动实质信息发生冲突时保留待核实说明，不能任取其一。不得改写报名链接中的必要参数。

严格使用 `references/data-contract.md` 的 JSON 结构，`kind` 为 `events`。`summary` 用简明文字说明活动做什么、参加方式或值得注意的变化，避免泛泛推荐；`details` 填入时间、截止、地点、参与形式、费用、主办方、报名方式。`personal_relevance` 无依据时为空字符串。

每个条目至少引用一个输入消息的真实 `id`；仅选择支持该条目的来源，不生成虚假引文。材料中没有合格活动时输出空 `items`，不得用闲聊凑数。覆盖或图片识别不完整时，说明限制，不称“所有群没有活动”。

## 分类、标签与地域

按具体活动或岗位填写主要分类 category 与少量主题标签 tags，群标签不能直接代替内容判断。优先使用配置中给定的分类候选，没有匹配时为“其他”。regions 仅填写材料支持的地域，通常为城市，必要时国家或区县；线下及混合活动无地域证据时填写“地域未注明”。不要添加地域确认状态，不根据来源群名字猜城市。来源引用使用真实消息 ID，群内发布时间由执行器从该消息提取。

无论所属群最终展示卡片还是精简表格，都执行同样的收录标准，不自行决定隐藏或排除某个群。

地域只使用与该活动相关、材料实际写出的地名，可规范“北京市”为“北京”；不自行补推上级省市。例如只写“东白山”时可用“东白山”作地域标签，不擅自扩成“浙江”。

一条消息可能提到多个活动或不同时间的直播。链接必须与当前条目所指的活动对应：前一天行前说明会的入口不能直接标作次日主活动报名/直播入口。若只提供相关说明链接，标题必须明确用途与日期；没有主活动链接时留空并保留原文参加方式。
